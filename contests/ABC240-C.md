# ABC240 C — Jumping Takahashi：同じ回数・同じ位置をまとめるDP

[問題ページ：ABC240 C — Jumping Takahashi](https://atcoder.jp/contests/abc240/tasks/abc240_c)

題名・URL・学習時のつまずきはユーザー共有の指示書に基づきます。公式本文への接続は環境の制限で拒否されたため、未確認の数値制約や公式サンプルは記載しません。以下の入力例は教材用の自作例です。

## 概要・使いどころ・判断

原点0から始め、各回iで与えられる正の距離aかbのどちらかへ進みます。N回全てのジャンプを行い、位置Xへちょうど到達できるかを判定します。

各回の選び方を全て試せば2^N通りですが、途中で**同じジャンプ回数・同じ位置**に来た経路は、その後に選べるジャンプが同じです。経路を全て持つのではなく、到達できる状態をまとめます。N回前にXへ来ても、残りのジャンプを飛ばして終わることはできません。

## 状態・初期条件・遷移・答え

2次元で考えると `reachable[i][j]` は「i回のジャンプ後に位置jへ到達可能か」。

- 初期状態：reachable[0][0]=True、それ以外False。
- 遷移：reachable[i][j]なら、j+aとj+bがX以下のときreachable[i+1]へTrueを立てる。
- 終了条件：N回処理後のreachable[N][X]が答え。

使うのは直前の行だけなので、現在行DPと次行nextDPの2配列へ圧縮できます。ループのiが回数を表しているため、各経路の回数を別に記録しません。

|変数|意味|
|---|---|
|i|今から処理するジャンプ（0始まり）|
|j|現在位置|
|DP[j]|i回を終えた位置jへの到達可否|
|nextDP[j]|i+1回を終えた位置jへの到達可否|

## 今回のつまずき1：同じ配列を前から更新

読みながらDPへ書くと、同じターンに新しく到達した位置を、また遷移元として使ってしまいます。例えばN=1、X=4、a=1,b=2なら本来は位置1か2にしか行けずNoです。しかし前から書き込むと0→1→2→3→4のように何度も進めてしまいます。

```diff
-for j in range(X):
-    if DP[j]:
-        DP[j+a] = True
-        DP[j+b] = True
+nextDP = [False] * (X+1)
+for j in range(X+1):
+    if DP[j]:
+        if j+a <= X:
+            nextDP[j+a] = True
+        if j+b <= X:
+            nextDP[j+b] = True
+DP = nextDP
```

上の誤り部分は、範囲チェックを足しても「同じターンで何度も進む」問題自体は直りません。

## 今回のつまずき2：DP = nextDPを内側へ置く

nextDPを導入しても、位置jを見ている途中でDPを差し替えると、まだ読むべき更新前の状態を失います。例えば2回目の直前に到達位置が{1,3}でも、j=0を処理しただけで空のnextDPへ差し替えると、その後1や3を読めません。

```mermaid
flowchart LR
    A["DP: i回後の全状態<br/>読み取り専用"] --> B["jを全て調べ<br/>nextDPへ書き込む"]
    B --> C["内側のループ終了後だけ<br/>DP = nextDP"]
```

## 最小限のPython実装

### 更新前後を分ける到達可能性DP

入力はN X、続くN行のa b。正のジャンプ距離を前提とし、位置Xを含む0〜Xを走査します。

```python
import sys
input = sys.stdin.readline
N, X = map(int, input().split())
DP = [False] * (X + 1)
DP[0] = True
for i in range(N):
    a, b = map(int, input().split())
    nextDP = [False] * (X + 1)  # 各回、空の次状態から作る
    for j in range(X + 1):
        if DP[j]:
            if j + a <= X:
                nextDP[j + a] = True
            if j + b <= X:
                nextDP[j + b] = True
    DP = nextDP  # 内側の走査が完了してから一斉反映
print('Yes' if DP[X] else 'No')
```

入力例：

```text
2 7
1 3
2 4
```

出力例：

```text
Yes
```

## 処理過程：経路が統合され、進めない経路は消える

|回数|選べる距離|X=7以下の到達位置|
|---|---|---|
|0|なし|{0}|
|1|1か3|{1,3}|
|2|2か4|{3,5,7}|

位置5には1+4と3+2の2経路がありますが、その後の到達可否には「5へ行ける」という1状態で十分です。方法数を数えるDPではないので重複して保持しません。

正の距離しか進まないため、一度Xを超えた位置はXへ戻れません。従って超過した状態を捨てられます。次のジャンプでX以下へ進めない古い状態は、空から作るnextDPに書き込まれず自然に消えます。途中で到達位置が空集合になれば、以後も空のままです。

## setで到達可能性を持つ別実装

位置の種類が少ない場合は、Falseを含む0〜Xの全走査を避けてsetを使えます。

### 到達した位置だけをsetへ保持

入力・出力は配列版と同じ。次の集合も別に作り、同じ回の新しい状態を読み直さないようにします。

```python
N, X = map(int, input().split())
reachable = {0}
for _ in range(N):
    a, b = map(int, input().split())
    next_reachable = set()
    for j in reachable:
        if j + a <= X:
            next_reachable.add(j + a)
        if j + b <= X:
            next_reachable.add(j + b)
    reachable = next_reachable
print('Yes' if X in reachable else 'No')
```

入力例：

```text
2 7
1 3
2 4
```

出力例：

```text
Yes
```

## 計算量・更新方向・応用

2次元DPを保存するとO(NX)空間ですが、2行だけ持つ配列版は **O(NX)時間・O(X)空間**（X≥1）。set版は到達位置の個数の総和に比例した平均時間で、上限はO(NX)、空間O(X)。setはハッシュ操作の平均で見積もり、常に配列より速いわけではありません。

|問題の条件|更新方向・旧状態の扱い|
|---|---|
|0/1ナップサック|降順に更新し、品物を使わない旧状態も残す|
|個数無制限の利用|同じ品物を再使用してよい場合、昇順を使うことがある|
|部分列を選ぶDP|後ろから更新し、今の文字を使わない旧状態も残す|
|今回：毎回必ず1回ジャンプ|更新前を読み、空のnextDPへ書く。旧状態を残すだけでは不正確|

今回も「逆順にすれば全て解決」ではありません。例えばX=2で、1回目が1か2、2回目が3か4なら、最後の答えはNo。1回目に立ったDP[2]を消さずに残すだけでは、2回目が実行できないのにYesになります。正の遷移について旧状態の消去も設計すればインプレース化できる場合はありますが、単なる方向変更ではなく、読み書きの時点を証明する必要があります。まずは2配列で安全に書く方針を優先します。

負のジャンプがある問題では、Xを超えた状態を切ってよいとは限りません。回数を省略したBFSのように同じ位置を全期間で訪問済みにするのも、残りの選択肢が違うため誤りです。

部分和・ナップサック、複数の選択肢から和を作る問題へ再利用できます。最初に状態を「何回目・どの位置」と定義し、経路そのものではなく将来に必要な情報だけを統合しましょう。[DPの基本](../learning-notes/03_dp.md)・[部分列DPの更新順](../techniques/subsequence-counting.md)・[B178の同時更新](paiza-B178.md)との共通点も確認してください。
