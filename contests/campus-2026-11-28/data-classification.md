# Q4：データの分類 — 変わったクラスだけで最頻値を更新する

[困りごと索引へ戻る](../../problem-solving-index.md) / [今回の振り返り](README.md)

## 問題・制約・確認範囲

点 `(x,y,c)` がN個ある。固定の分類対象 `(x0,y0)` に近いK個を選び、その中の最頻クラスを答える。Kは**点の個数**であり、半径ではない。距離同点は小さいクラスの点を先に選ぶ。頻度同点も小さいクラスを答える。

共有制約は `N ≤ 10^5`、`Q ≤ 10^5`、`1 ≤ c ≤ 10^9`、`1 ≤ K ≤ N`。座標の範囲は未確認。入力はN、N行の `x y c`、`x0 y0`、Q、Q行のK。出力はクエリ順にクラスを1行ずつ。問題名・Q4という表記・仕様はユーザー共有の復習記録に基づく。

## 本番のつまずきと素直な方法

Kを半径と解釈し、距離を対象座標基準で計算できず、頻度最大値の効率的な管理も思いつかなかった。まず仕様を「近い点をK個」と書き直す。

距離の順序は `(x-x0)**2 + (y-y0)**2` で比較できる。平方根を取る必要はない。`(二乗距離, クラス番号)` をソートすると点を選ぶ順序が決まる。同じ2値の点は入れ替えても頻度が同じなので追加の優先条件は不要。

ソート後、各クエリで先頭K点を数え直す方法は最悪 O(NQ)（別途ソート O(N log N)）。さらに、各接頭辞で辞書全体を見て最頻値を求める方法も、すべて異なるクラスなら合計 O(N² + Q)。毎回変わるのは何かを考える。

## 追加したクラスだけが追い越せる

`freq[c] += 1` で変わるのはcだけ。他のクラス同士の順位は変わらない。したがって、以前の最頻クラスとcを比べれば、新しい最頻クラスが分かる。

- `freq[c] > max_cnt`：cが新しい最頻。回数とクラスを更新する。
- `freq[c] == max_cnt`：番号が小さい方を選ぶ。
- それ未満：答えは変わらない。

各接頭辞の答えを `ans` に保存すると、K個の場合は `ans[K-1]`。これは区間和の累積和ではなく、接頭辞ごとの**答えの事前計算**である。

## コードと原版からの変更点

[元のACコード](data_classification.py)はユーザーからAC済みとして共有されたものをそのまま保存した。こちらで再提出してACを確認したわけではない。[整理版](data_classification_improved.py)は `defaultdict(int)` で初期化用の走査をなくし、アンパックと `elif` で比較の意図を表した。整理版はローカル検証のみ。

原版の2個の `if` は誤りではない。新記録の後の同率判定は `min(c,c)` になるだけ。`best_class = 0` も最初の回数1が必ず新記録になるため正しく置き換わる。また、辞書を0にするループは集計前なので、同じクラスを何度初期化しても集計結果を消してはいない。

## 正しさ・計算量・再利用

ソートにより各Kの選択対象が接頭辞になる。空から始め、上の3分岐が最頻値と同率時の最小番号を維持するので、帰納的にすべての接頭辞の答えが正しい。クエリは対応する答えを読むだけ。

時間 O(N log N + Q)、空間 O(N)。辞書操作は平均 O(1) とする。単一クラス、等距離、同頻度、K=1、K=N、分類対象が原点以外のケースを確認する。点や分類対象がクエリごとに変わるなら、同じソートと答え表は使い回せない。

また、頻度の**減少や削除**があると、元の最頻値が下がって他クラスに抜かれる場合があり、この更新方法はそのまま使えない。
