# ABC284 C — Count Connected Components：根の種類を数える

[問題ページ：ABC284 C — Count Connected Components](https://atcoder.jp/contests/abc284/tasks/abc284_c)

題名・URL・学習時のつまずきはユーザー共有の指示書に基づきます。公式本文への接続は環境の制限で拒否されたため、未確認の数値制約や公式サンプルは記載しません。以下の入力例は教材用の自作例です。

## 問題を既存の手法へ落とし込む

N頂点M辺の無向グラフについて、連結成分の個数を求めます。「つながるグループを全部数える」という目的で、辺の長さや最短経路は必要ありません。孤立頂点も1成分です。

BFS/DFSで全成分を探索しても解けますが、今回学ぶのは辺の両端のグループをUnion-Findで結ぶ方法です。最初はNグループ、異なるグループを結ぶたび1つ減らします。

## 今回のつまずき

根を調べず `parent[x] = y` としていた点が課題でした。これはグループ全体を結ぶのではなく、x以下の一部を別へ付け直してしまう場合があります。[Union-Findの詳説](../algorithms/union-find.md)に、{0,1,2}が分離してしまう反例を載せています。

## 最小限の実装・変数

標準実装は[Union-Findのテンプレート](../algorithms/union-find.md)の1か所に置き、この問題の入力形式N M、続くM行の1始まりの辺に対応させています。同じクラスをここへ複製しません。

- parent：グループの根へ向かう内部の親。
- find：途中の親ではなく、根までたどる。
- group_count：結合に成功した場合だけ減らす。
- size：根で保持するグループの人数。

入力例（自作）：

```text
6 3
1 2
2 3
4 5
```

期待する出力：

```text
3
```

追加ごとの成分数は6→5→4→3。最終的な根の集合は内部0始まりで{0,3,5}となり、全頂点へfindを適用して集合化しても3個です（根の具体的な番号は結合順・実装次第）。

## 計算量・反例・応用

標準DSUは初期化O(N)、M回の結合が償却O(Mα(N))、最後の成分数取得O(1)、空間O(N)。全ての辺を保存する必要がありません。BFS/DFSならO(N+M)時間・隣接リスト込みO(N+M)空間です。

既に同じ根の辺を追加しても成分数は減りません。M本の辺があるからN-M成分と決め打ちすると、閉路を含む場合に誤ります。例えば三角形はN=M=3でも成分数1であり、0にはなりません。

同じグループか、人数はいくつか、削除クエリを逆順に戻すにはどうするかなどの発展は[Union-Findの詳説](../algorithms/union-find.md)へ進んでください。

## 検証

検証ではBFSの連結成分数と比較し、三角形・孤立頂点も確認しています。find/same/sizeと結合成功時の成分数は標準DSUのテストで独立なグループ管理と照合しています。 [専用テスト](../tests/test_atcoder_five_topics.py)は教材のコードそのものを読み取り、実行します。
