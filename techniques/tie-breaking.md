# 同点処理：比較条件を1か所にまとめる

## 同じ値でも結果が変わる

[ABC483 C](../contests/ABC483-C.md)の勝者は得票数が最大、同票なら候補者番号が最小の人です。得票数だけで比較すると、探索順によって誤った番号を返すことがあります。上位2候補の前計算と更新後の比較で、同じ規則を使います。

## タプル比較の対応表

候補者iの得票を `votes[i]` とし、インデックスを0始まりとします。

|関数|キー|意味|
|---|---|---|
|`min()`|`(-votes[i], i)`|票が多い、番号が小さい方を選ぶ|
|`max()`|`(votes[i], -i)`|同じ規則で選ぶ|
|`sorted()`|`(-votes[i], i)`|良い順に全候補を並べる|

`min`と`max`はN要素を調べると $O(N)$、sortedは $O(N\log N)$。候補者1人ずつのキー比較は通常 $O(1)$ です。同票時に小さい番号を選びたいのに `max(..., key=lambda i: (votes[i], i))` とすると逆になります。

## 実行可能な境界テスト

```python
cases = [
    ([2, 2, 1], 0),  # 同率1位が複数
    ([0, 0, 0], 0),  # 全員同じ値（一般的な比較関数のテスト）
    ([0, 3, 3], 1),  # 先頭以外が同率1位
    ([1, 0], 0),     # 要素数2
]
for votes, expected in cases:
    ids = range(len(votes))
    best_min = min(ids, key=lambda i: (-votes[i], i))
    best_max = max(ids, key=lambda i: (votes[i], -i))
    best_sort = sorted(ids, key=lambda i: (-votes[i], i))[0]
    assert best_min == best_max == best_sort == expected
print('OK')
```

出力は `OK` です。各配列長をNとすると、ソートを含む各ケースの時間は $O(N\log N)$、空間 $O(N)$ です。全員0票は比較方法の一般テストであり、Mが1以上の本問で全投票後の全員が0票になる例ではありません。

## 境界条件の考え方

- 最大値が同じ2人の片方を除外しても、もう一方の最大値を使えるか。
- 加票で相手と同票になったとき、小さい番号が勝つか。
- 加票先が元の最良候補自身のときも結果が保たれるか。
- 番号の0始まり・1始まりを混ぜていないか。

`max`はキーが等しい場合、最初に現れた要素を返します。番号もキーに入れれば列挙順への依存をなくせます。空集合ではmin/maxは例外になるため、少なくとも1候補が残る条件も確認します（本問はNが2以上）。
