# 二部マッチング：DFSを「ペアを組み替える探索」に変える

[二部グラフ判定](dfs-bfs-advanced.md)の次に読む発展編です。BFS/DFSは探索手法、最大マッチングは「どの探索を何度行って最適化するか」というアルゴリズムです。

<a id="basic-matching"></a>

## 11. DFSによる二部マッチングの基本

**用途・特徴**：「1人に1つだけ割り当てる」「隣接した2マスを重ならず組にする」「割当を最大個数」。左集合Lと右集合Rの間だけに辺があり、各頂点を高々1回しか使えない組を選びます。選んだ辺の集合がマッチング、その本数が最大になるものが最大マッチングです。

## なぜ到達判定やUnion-Findだけでは足りないか

到達性はつながっていればYesですが、ペアには「同じ頂点を2回使えない」という競合があります。単に通れる場所にvisitedを付けるだけでは、いま決めている相手の変更を表現できません。

|4頂点の連結グラフ|最大のペア数|
|---|---|
|道: 0–1–2–3|2（0–1、2–3）|
|星: 中央0と葉1,2,3|1（中央を何度も使えない）|

どちらも連結成分1個・サイズ4です。Union-Findが保持する連結性だけから、この違いを決められません。連結成分ごとの処理分割に使えることはありますが、最大マッチング自体は別に求める必要があります。

## 増加道：既に決めた相手も、別の相手へ動かしてよい

左0は右a,bのどちらでもよく、左1は右aしか選べないとします。先に左0→aを選ぶだけでは左1が困ります。しかし左0をbへ変更すれば、左1→aを追加できます。

```mermaid
flowchart LR
    U["左1: 未割当"] -.->|"使いたい辺"| A["右a"]
    A -->|"現在のペアを逆にたどる"| V["左0"]
    V -.->|"別の候補"| B["右b: 未割当"]
```

この「未使用の辺→使用中の辺→未使用の辺…」と交互に進み、両端が未割当の道を**増加道**と呼びます。道に沿って使用・未使用を反転すると、マッチングの本数が1増えます。

|段階|右aの相手|右bの相手|本数|
|---|---|---|---|
|最初の割当後|左0|なし|1|
|探索で左0の代替先bを発見|組み替えを準備|組み替えを準備|まだ1|
|帰りがけにペアを変更|左1|左0|2|

### 普通のDFSとの接続

- 状態：今、代わりの相手を探している左頂点u。
- 遷移：隣の右頂点vが埋まっていれば、その相手の左頂点へ進む。
- 成功条件：空いている右頂点を見つける。
- 帰りがけ：奥が成功したら、その手前の相手をuへ差し替える。

ここでseenは「この1回の増加道探索で、既に調べた左頂点」です。普通の到達探索のように全実行を通じて永久に訪問済みにしてはいけません。ペアが変わると、別の増加道を新たに探す必要があるからです。

### 小規模な二部グラフをDFSで解く

入力はL R E、E行の左u 右v（両側とも0始まりの別々の番号）。最大ペア数を出力。学習・小入力用の再帰実装です。

<!-- example: kuhn-matching -->
```python
import sys
input = sys.stdin.readline
left_count, right_count, e = map(int, input().split())
adj = [[] for _ in range(left_count)]
for _ in range(e):
    u, v = map(int, input().split())
    adj[u].append(v)

def maximum_matching(adj, right_count):
    pair_right = [-1] * right_count
    seen = [0] * len(adj)
    stamp = 0

    def dfs(u):
        if seen[u] == stamp:
            return False
        seen[u] = stamp
        for v in adj[u]:
            other = pair_right[v]
            if other == -1 or dfs(other):
                pair_right[v] = u  # 奥が成功したら、帰りがけに相手を差し替える
                return True
        return False

    answer = 0
    for u in range(len(adj)):
        if not adj[u]:
            continue
        stamp += 1  # 配列を毎回消す代わりに、探索番号で訪問済みを分ける
        if dfs(u):
            answer += 1
    return answer

print(maximum_matching(adj, right_count))
```

入力例：

```text
2 2 3
0 0
0 1
1 0
```

出力例：

```text
2
```

### 変数と処理順

`pair_right[v]` は右vの現在の相手（左の番号）、-1なら空き。stampは新しい探索を始めるたびに変える番号です。seen[u]がその番号なら、今回の探索でuを再帰的に巡回しないよう止めます。

例では、dfs(0)が右0を確保。dfs(1)は右0の相手である左0へ進み、左0は右1へ移れます。その帰りに右0の相手を左1へ変えて、答え2になります。失敗した枝ではペアを変更しないため、未完成の組み替えが残りません。

### 計算量・正しさ・注意点

左頂点数をL、全頂点数をV=L+Rとします。1回の探索は辺をO(E)回調べ、最大L回なので **O(L×E+V)**。孤立した左頂点はスキップし、訪問配列はstampで区別しているため、各回に配列全体を初期化する費用はありません。一般にはO(VE)と紹介される基本法です。空間はO(V+E)、再帰の深さは最大O(L)です。

増加道を1本見つければ確実に1組増えます。もう増加道がないなら最大です。より大きいマッチングがあると仮定して両者の異なる辺を比べると、辺が交互に並ぶ道・閉路に分かれ、より大きい側が1本多い道が少なくとも1本存在します。それが今のマッチングを増やせる道なので、「増加道がない」に矛盾します。

辺を適当に選んでこれ以上直接追加できなくなっただけの状態は**極大**であり、最大とは限りません。上の1組の状態でも直接追加はできませんが、組み替えれば2組になります。再帰上限を増やしてもO(VE)の遅さは変わりません。9万頂点のS082へこのまま使わないでください。

## 高速化：Hopcroft–Karp法のBFS＋DFS

基本法は「1本増やすたび、全体を探し直す」ため遅くなります。Hopcroft–Karp法は次の2段階を1フェーズとして繰り返します。

1. **BFS**：全ての未割当の左頂点から同時に、最短の増加道の層を作る。
2. **DFS**：その層を1つずつ進む道だけを探し、複数の最短増加道をまとめて処理する。

通常のBFSとの違いは、「空いている右へ進むか、埋まっている右を通じてその相手の左へ進む」という遷移です。DFSは全ての道を調べるのではなく、BFSで作った層だけを進みます。

```mermaid
flowchart LR
    A["未割当の左<br/>層0: 左1"] --> B["右aは左0とペア"]
    B --> C["層1: 左0"]
    C --> D["空き右b<br/>最短増加道が完成"]
```

先ほどの例では、第1フェーズで左0→右aが決まります。次のBFSで左1が層0、右aの相手の左0が層1になります。DFSで左1→右a→左0→右bをたどり、ペアを反転します。左頂点だけの層が0,1なら、実際の増加道の辺数は3です。

### 完全な反復実装はS082の1か所に置く

[paiza S082の実装](../contests/paiza-S082.md)に、再帰を使わない `hopcroft_karp(adj, right_count)` を掲載しています。同じ長い実装を重複させず、ここでは各部の役割を対応付けます。

|変数・処理|意味|
|---|---|
|pair_left / pair_right|現在の左右のペア。-1なら未割当|
|dist|BFSが作る左頂点の層|
|shortest|空き右に届く最短の層数（左側の移動単位）|
|build_layers|全未割当の左から始め、最短の増加道の層を構築|
|next_edge[u]|このフェーズでuの次に試す隣接辺。何度も最初へ戻らない|
|stack / chosen_right|探索中の左の経路と、間に選んだ右頂点|
|augment|層を進んで空き右へ到達し、経路全体のペアを反転|

失敗した左頂点はそのフェーズで到達不能の層にして、同じ行き止まりを再探索しません。1フェーズの走査はO(V+E)。最短増加道をまとめて処理すると、その長さが増え、フェーズ数はO(√V)に抑えられます。長さが√V未満の段階は高々O(√V)段階、長くなった後は頂点を重複しない増加道の本数が高々O(√V)本で、最適との差もその程度だからです。

従って、孤立点も含めた安全な表記で **O((V+E)√V)**、孤立点を除いた通常の表記はO(E√V)です。空間O(V+E)。S082のグリッドはE=O(V)なのでO(HW√(HW))となります。DFS版のO(VE)とは区別してください。

### 使い分け

小規模でペアの組み替えを学ぶなら基本DFS。大規模な二部グラフならHopcroft–Karp。辺に利益・費用が付くなら、最大**本数**だけのアルゴリズムでは目的を満たしません。また一般グラフの最大マッチングへ二部用実装をそのまま流用できません。
