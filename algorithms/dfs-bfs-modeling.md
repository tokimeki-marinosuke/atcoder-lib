# 問題文からグラフへ：頂点・辺・状態を設計する

## 先にコードを書かず、5つの質問に答える

1. **状態**：今後できる行動を決めるため、何を覚える必要があるか。
2. **頂点**：区別すべき状態1つを1頂点とする。
3. **辺**：1回の許された操作で、どの状態へ移れるか。
4. **目的**：到達・距離・全グループ・組み合わせのどれか。
5. **規模**：頂点数と遷移数は最大いくつか。配列を確保できるか。

```mermaid
flowchart LR
    A["問題文の操作と制約"] --> B["状態を決める<br/>未来の行動に必要な情報"]
    B --> C["1操作を辺にする<br/>向き・コストも決める"]
    C --> D["目的から選ぶ<br/>到達・最短・割当"]
    D --> E["状態全体を添字にして実装"]
```

## 頂点・辺・状態・訪問済みの関係

「同じマス」ではなく「将来の行動が同じになる状態」を同じ頂点として扱います。位置が同じでも、鍵を持つかどうかで通れる扉が変わるなら別頂点です。訪問済みも座標だけでなく状態全体で管理します。

逆に、将来に影響しない過去の経路そのものを全て状態に入れると、状態数が爆発します。普通の迷路では同じ座標に最短で着けば、その先の行動は同じなので、最初の到達後に長い経路で来ても探索を省けます。0-1 BFSなどでは「最初」ではなく、距離を改善できるかが基準です。

## 隣接リストを作る場合・作らない場合

|形式|頂点|辺の作り方|訪問のキー|
|---|---|---|---|
|道の一覧が入力される|街番号|入力の各道をgへ登録|番号v|
|通常のグリッド|座標(r,c)|上下左右をその場で生成し、範囲・壁を確認|(r,c)|
|鍵1個の迷路|座標と所持状態|移動先の扉条件を確認し、鍵なら状態更新|(r,c,key)|
|向きによって追加コスト|座標と向き|次の方向を決めて移動、方向変更なら加算|(r,c,direction)|
|空きマスを2つずつ組にする|空きマス|上下左右の空きマス同士を結ぶ|マッチングの左右の頂点番号|

グリッドは隣接リストを作らず、その場で4近傍を調べられます。通常のグリッドならV=HW、候補の遷移は各頂点4本以下でE=O(HW)。有向の操作では逆向きへ勝手に移動できるとしないでください。例えば「数を2倍する」操作があっても「半分にする」が許されるとは限りません。

## 例題A：街の道で、始点から目的地へ行けるか

**問題文**：道を何本でも通ってよい。行けるかだけ答える。  
**変換**：街を頂点、道を辺。相互通行なら両向き。  
**選択**：BFSでもDFSでもよい。最短の移動回数が必要になればBFS。  
**実装**：[実践編1・2](dfs-bfs-patterns.md)でvisitedとdistを選ぶ。

辺の入力が1始まりなら、読み込み時に-1する方針を統一します。頂点番号と配列の長さを確認します。

## 例題B：壁のある迷路で最短何回か

**問題文**：上下左右の空きマスへ1歩で移動。  
**変換**：歩ける座標が頂点、壁ではない4近傍が辺。壁を通る辺は作らない。  
**選択**：全て1歩なのでBFS。  
**実装**：[実践編3](dfs-bfs-patterns.md)の座標探索と[実践編4](dfs-bfs-patterns.md)の経路復元を組み合わせる。

```text
S.#     S=(0,0) からは (0,1)、(1,0) へ移れる
..G     壁=(0,2) への辺は作らない
```

2次元配列を使うか、`id = r*W+c` で1次元化します。逆変換は `r,c = divmod(id,W)`。距離配列はH行W列です。`[[False]*W]*H` は行を共有するため使わず、内包表記で別々に作ります。

## 例題C：鍵を取ると扉を通れる迷路

**問題文**：鍵を取った後は、以前は通れなかった扉を通れる。  
**変換**：`(r,c,has_key)`。1個の鍵なら状態数は最大2HW。  
**選択**：各移動が1歩なら状態BFS。  
**実装**：[状態BFS](dfs-bfs-states.md)。座標だけのvisitedでは、鍵を取って同じ場所へ戻る探索を誤って止めます。

```mermaid
flowchart LR
    A["位置S・鍵なし"] --> B["鍵aを取る"]
    B --> C["位置S・鍵あり<br/>初めのSとは別状態"]
    C --> D["扉Aを通ってゴール"]
```

鍵の種類がk個なら所持集合をbitで表して状態数は最大HW×2^k。鍵を使って消費するか、再入手できるかでも遷移が変わります。向きや残り回数を状態へ足す場合も、状態数の積を先に計算します。

## 例題D：隣り合う空きマスを、重ならずに組にする

**問題文**：2マスのタイルをできるだけ多く置く。  
**変換**：空きマスを頂点、上下左右の空きマスを辺。ただし「通れるか」ではなく「端点を重複使用しない辺を最大何本選ぶか」。  
**選択**：市松模様で二部グラフにし、最大マッチング。普通のBFSで到達数を数えても答えになりません。  
**実装**：[二部マッチング](bipartite-matching.md)から[paiza S082](../contests/paiza-S082.md)へ進む。

## アルゴリズムの選択表

|道具|答えられる主な質問|ここだけではできないこと|
|---|---|---|
|BFS|等コストの最短距離、到達性|辺の両端が重ならない最大割当を直接求める|
|DFS|到達性、木の集計、探索の行き帰り|一般グラフで初回到達を最短距離とみなす|
|Union-Find|無向の連結成分、辺追加時の連結性|経路・距離・最大マッチングを直接求める|
|Dijkstra|非負重みの最短距離|負辺にそのまま適用する|
|最大マッチング|互いに端点を共有しない辺の最大本数|単なる連結成分の大きさだけから決める|

BFS・DFSは**探索の順序を決める手法**です。最大マッチングでは探索する対象を「増加道」に変えて内部で利用します。別々の競合する名前ではなく、探索がより大きなアルゴリズムの部品になる関係です。

## 演習

**Level 3：ジャンプを1回だけ使える迷路なら、visitedは何を区別する？**

<details markdown="1"><summary>ヒント</summary>

同じ座標でも、まだジャンプできる場合と使い切った場合の行動は同じでしょうか。

</details>

<details markdown="1"><summary>解説</summary>

(r,c,used_jump)を状態にします。普通の移動はused_jumpを維持し、ジャンプは未使用の状態からだけ使用済みへ遷移します。使える回数がTなら残り回数も考え、状態数HW(T+1)を見積もります。

</details>
